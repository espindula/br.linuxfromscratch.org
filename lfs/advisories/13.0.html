LFS Security Advisories for LFS 13.0.

LFS-13.0 was released on 2026-03-05

This page is in alphabetical order of packages, and if a package has multiple advisories the latest one comes first.

The links at the end of each item point to additional details which have links to the development books.

Glibc

Updating Glibc from an earlier version on a running LFS system requires extra precautions to avoid breaking the system. The precautions are documented in an "Important" box of the LFS book section for Glibc. Follow it strictly or you may render the system completely unusable.

13.0 067 glibc (LFS) Date: 2026-05-22 Severity: Critical

In glibc-2.43, three security vulnerabilities were discovered that could allow for denial of service (application crashes) and possibly arbitrary code execution and information disclosure. Users should rebuild glibc with the consolidated patch in the development book immediately. Note that rebuilding glibc should be done with extreme caution, and the instructions on that page should be followed strictly to prevent a broken system. 13.0-067

13.0 021 glibc (LFS) Date: 2026-04-01 Severity: High

In glibc-2.43, two security vulnerabilities were discovered that could allow for applications to treat invalid DNS responses as valid. These issues are both classified as violations of the DNS specification, and were resolved by counting the amount of records expected as well as performing input validation on hostnames in DNS records. Users should rebuild glibc with the sed in the development book. Note that rebuilding glibc should be done with extreme caution, and the instructions for updating glibc on that page should be followed strictly to prevent a broken system. 13.0-021

Expat

13.0 069 Expat (LFS) Date: 2026-05-22 Severity: High

In Expat-2.8.1, a security vulnerability was fixed that could allow for a denial of service (application crash and excessive resource consumption) when processing crafted XML input. The underlying problem was due to extreme computational complexity of the attribute name collision checks. Update to Expat-2.8.1 as soon as possible. 13.0-069

13.0 065 Expat (LFS) Updated: 2026-05-22 Severity: Low

In Expat-2.8.0, a security vulnerability was fixed that could allow for hash flooding when processing a crafted XML file. The issue occurs due to insufficent entropy in the current hash flooding protection implementation, where 4 to 8 bytes of entropy are used on a salt when up to 16 are actually supported. Update to Expat-2.8.0. 13.0-065

Updated on 2026-05-22 for a grammar fix in the consolidated advisory. No changes were made to this page for this advisory.

inetutils

13.0 064 inetutils (LFS) Date: 2026-04-30 Severity: Critical

In inetutils-2.8, three security vulnerabilities were resolved in the telnet server that could allow for remote code execution, information disclosure, privilege escalation, and authentication bypass. Linux Kernel

13.0 098 Linux Kernel (LFS) Date: 2026-05-28 Severity: Critical

In Linux-7.0.10 and 6.18.33, two security vulnerabilities were fixed that could allow for local privilege escalation. These are amongst the same class as CopyFail, as both of them have proof of concept exploits that allow for extremely trivial local privilege escalation by overwriting a version of /usr/bin/su in the page cache, which is never written to disk. The first vulnerability has been termed Fragnesia, and it involved the XFRM ESP-in-TCP subsystem in the kernel which is enabled by default via a 'make defconfig'. Because of this, it is reasonably assumed that all LFS users who are running a Linux-4.9.x kernel or later are affected by this issue (and the first release of LFS to include a kernel affected was LFS 8.0). The other vulnerability has been termed PinTheft, which affected the RDS module combined with the io_uring subsystem. Thankfully though the RDS module is not enabled by default in the kernel, so only users who have explicitly enabled CONFIG_RDS are vulnerable to this issue. The first LFS version affected by this issue is 8.3 (from 2018). Similar to CopyFail and other derivatives, these vulnerabilities disable password authentication for 'su' until the system is rebooted or the page cache is emptied. Note that while local privilege escalation has been identified as one of the primary impacts, these vulnerabilities are being chained together with exploits in other packages to give remote attackers root access on a system once it has been compromised via other means. ALL users of LFS must immediately update to Linux-6.18.33 or 7.0.10. The importance of updating cannot be underscored enough. Users also must take care of other security updates to reduce exposure as soon as possible. Please continue to monitor the Consolidated Advisories page for further updates. 13.0-098

13.0 066 Linux Kernel (LFS) Date: 2026-05-21 Severity: Critical

In Linux-7.0.9 and 6.18.32, several recent high profile vulnerabilities were resolved. These vulnerabilities have been termed CopyFail, DirtyFrag, DirtyCrypt, and ssh-keysign-pwn. All four vulnerabilities allow for extremely trivial privilege escalation, and CopyFail in particular overwrites the su binary in memory via the page cache, allowing it to bypass any and all password verification until the system has been rebooted. ssh-keysign-pwn is named after one of the working exploits for this vulnerability, which allows an unprivileged attacker to read the contents of ssh_host_*_key or /etc/shadow (via the 'chage -l' command). All four of these vulnerabilities have weaponized exploits available, and are under active exploitation at this time. LFS versions back to LFS 9.1 are confirmed to be affected by CopyFail, as are most distros from 2017 onwards as the functionality required to exploit it is built into the kernel via 'make defconfig'. At this time, two additional vulnerabilities of the CopyFail class termed Fragnesia and PinTheft have not been resolved, but also are under active exploitation. Note that while local privilege escalation has been identified as one of the primary impacts, these vulnerabilities are being chained together with exploits in other packages to give remote attackers root access on a system once it has been compromised via other means. ALL users of LFS must immediately update to Linux-6.18.32 or 7.0.9. The importance of updating cannot be underscored enough. Users also must take care of other security updates to reduce exposure as soon as possible. Please continue to monitor the Consolidated Advisories page for further updates. 13.0-066

OpenSSL

13.0 039 OpenSSL (LFS) Date: 2026-04-15 Severity: Medium

In OpenSSL-3.6.2, seven security vulnerabilities were fixed that could allow for contents of uninitialized memory to be sent to a malicious peer, for denial of service (application crashes), and arbitrary code execution. These occur in a variety of contexts in OpenSSL, including when applications use RSASVE key encapsulation to establish a secret encryption key, when applications use AES-CFB128 encryption or decryption on systems that support the AVX-512 instruction set, when clients are configured to perform DANE TLSA-based server authentication, when processing a delta CRL, when processing CMS EnvelopedData messages with KeyAgreeRecipientInfo, when processing CMS EnvelopedData messages with KeyTransportRecipientInfo, and when performing hexadecimal strings on 32-bit platforms. Update to OpenSSL-3.6.2. If you are still on a *LFS 12.4 system, use 3.5.5. 13.0-039

13.0 038 Python (LFS and BLFS) Date: 2026-04-15 Severity: Critical

In Python-3.14.4 (and 3.13.13), four security vulnerabilities were fixed. After release though, an additional four were resolved. These vulnerabilities can allow for a variety of impacts, including denial of service (application crashes), allowing data to be accepted by the base64 module that should've been processed differently, for input validation bypasses when working with cookies in http.Cookies.Morsel (allowing injection of control characters into cookies), for legacy *.pyc files to be incorrectly handled (leading to unintentional behavior at runtime for various programs), for arbitrary code execution when processing LZMA, BZ2, or GZIP compressed files in Python, for CR/LF bytes to not be rejected by HTTP client proxy tunnel headers, for commands to be injected into the underlying shell when a Python script opens a web browser, and for memory corruption to occur when using the remote debugging feature in Python 3.14 and later. Update to Python-3.14.4 with the security fixes patch. BLFS 12.4 users can safely use 3.13.13 with the patch but will need to skip a missing file during the patch process. 13.0-038

sed

13.0 068 sed (LFS) Date: 2026-05-22 Severity: Low

In sed-4.10, a security vulnerability was fixed that could allow for an attacker to overwrite a file with attacker-controlled content due to a TOCTOU race condition. In order for this vulnerability to be exploited, a user must invoke sed with both the '-i' and the '--follow-symlinks' options, and an attacker must replace the target of a symlink within an extremely small window of time. Because of this reason, upstream has marked the vulnerability as low. Update to sed-4.10. 13.0-068

xz

13.0 018 xz (LFS) Date: 2026-04-01 Severity: Critical

In xz-5.8.3, a security vulnerability was fixed that could allow for a buffer overflow to occur in the lzma_index_append() function that could possibly allow for arbitrary code execution in some rare circumstances. Upstream has noted that it's very unlikely that the bug can be triggered in any real-world application, but the vulnerability has been marked as Critical nonetheless. The vulnerablity occurs if lzma_index_decoder() was used to decode an Index that contains no Records, as the resulting lzma_index was left in a state where a subsequent lzma_index_append() would not allocate enough memory, and thus the buffer overflow occurs. However, there typically isn't a reason to append Records to a decoded lzma_index. Update to xz-5.8.3. 13.0-018
